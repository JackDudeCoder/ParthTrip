### Bugfix: Admin Privileges Desync on New Admin Account
- **Resolved "Forbidden: Admin privileges required." on Trip Creation**:
  - In `app/admin/employees/actions.ts` (`ensureAdminCompany`), initialized `createAdminClient()` early to bypass RLS and checked role against both `profile.role` and `user.user_metadata.role`.
  - Added self-healing upsert so that any admin account whose `public.profiles.role` was defaulted to `'employee'` is automatically updated to `'admin'`, satisfying PostgreSQL's `public.is_admin()` RLS check.
  - In `app/admin/trips/actions.ts` (`createTripAction`), switched insertions of `trips` and `trip_assignments` to `dbClient` to prevent Next.js server cookie/RLS caching race conditions.
  - In `app/login/page.tsx`, updated `handleLogin` and `handleRegister` to respect metadata role and sync database profile directly.
  - Production build re-executed and verified cleanly (`exit 0`).
